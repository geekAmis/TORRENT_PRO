**TORRENT_PRO** — это высокопроизводительная, масштабируемая многопользовательская система управления торрентами. Система позволяет пользователям легко управлять загрузками через Magnet-ссылки или `.torrent` файлы, заточенная под сервера с высокой скоростью загрузки, при этом обеспечивая строгое соблюдение лимитов ресурсов (объем данных и количество торрентов) в рамках подписочной модели.

## ✨ Ключевые возможности

### 🛡️ Продвинутое управление пользователями
* **Интеграция Google OAuth2:** Безопасная и мгновенная авторизация через Google.
* **Система подписок:** Гибкое управление доступом. Администраторы могут задавать лимиты для:
    * `Лимит МБ`: Максимальный объем скачанных данных.
    * `Лимит Торрентов`: Максимальное количество активных загрузок.
* **Автоматизация профилей:** Система автоматически создает профиль и синхронизирует данные (аватар, email) при первом входе.

### 📥 Торрент-движок (на базе libtorrent)
* **Гибридное добавление:** Поддержка как **Magnet-ссылок**, так и физических **.torrent файлов**.
* **Умное возобновление:** При перезагрузке сервера система сканирует БД и автоматически возобновляет все незавершенные загрузки.
* **Мониторинг в реальном времени:** Асинхронные фоновые задачи отслеживают скорость, прогресс, количество пиров и статусы.
* **Общая библиотека (Global Sharing):** Если пользователь добавляет торрент, который уже качается другим участником системы, он мгновенно "привязывается" к его библиотеке без повторного расхода трафика.

### 👨‍💼 Панель администратора
* **Контроль пользователей:** Мониторинг статистики загрузок и статусов подписок.
* **Управление тарифами:** Создание новых уровней доступа и назначение их пользователям "на лету".
* **Полный контроль:** Управление всей экосистемой торрент-сервера через API.

## 🏗️ Архитектура

Проект построен на современной асинхронной архитектуре:

* **Backend:** `FastAPI` для обработки высоконагруженных API-запросов.
* **Frontend:** `Flask` для обеспечения веб-интерфейса.
* **Torrent Core:** `libtorrent`, обернутый в `asyncio` задачи для неблокирующего мониторинга.
* **Database:** `SQLAlchemy` + `PostgreSQL` для хранения данных пользователей, метаданных файлов и уровней подписки.
* **Concurrency:** Использование `asyncio.create_task` для независимого мониторинга каждого активного хэша.

## 🚀 Быстрый старт

### Предварительные требования
* Python 3.9+
* Установленный системный пакет `libtorrent`
* Проект в Google Cloud Console (для OAuth-ключей)

### Установка

1. **Клонируйте репозиторий**
   ```bash
   git clone https://github.com/geekAmis/TORRENT_PRO.git
   cd TORRENT_PRO
   ```

2. **Установите зависимости**
   ```bash
   python3 -m venv venv && source venv/bin/activate
   pip install -r requirements.txt
   ```

3. **Настройка окружения**
   Создайте файл `.env` или обновите `config/init.py`:
   ```env
   GOOGLE_CLIENT_ID=ваш_id.apps.googleusercontent.com
   GOOGLE_CLIENT_SECRET=ваш_секрет
   SECRET_KEY=ваш_секретный_ключ_jwt
   ADMIN_EMAILS={'admin@example.com', ...}
   ```

4. **Запуск API сервера**
   ```bash
   uvicorn main:app --host 127.0.0.1 --port 8000 --proxy-headers --forwarded-allow-ips '*'
   ```

5. **Запуск Web-клиента**
   ```bash
   cd ./web
   gunicorn -w 4 -b 127.0.0.1:80 app:app
   ```

<details>
  <summary>Подробное объяснение от Gemma 3</summary>

Этот код представляет собой ядро (Backend) системы управления торрентами на базе **FastAPI**. Система реализует сложную логику: авторизацию через Google, управление подписками (лимиты на объем и количество файлов), асинхронный мониторинг закачек через `libtorrent` и общую библиотеку файлов (если один файл качают двое, он качается один раз).

Ниже приведен подробный разбор.

---

### 1. Глобальные переменные и инициализация
*   **`app`**: Экземпляр FastAPI.
*   **`ses`**: Объект сессии `libtorrent.session()`. Это "движок", который управляет всеми сетевыми соединениями и скачиванием.
*   **`active_downloads`**: Словарь `{hash: asyncio_task}`, где хранятся запущенные фоновые задачи мониторинга, чтобы не запускать их дважды для одного файла.
*   **`DOWNLOAD_DIR`**: Путь к папке, куда сохраняются файлы (из `config.init`).
*   **`RESUME_DATA_FILE`**: Путь к файлу, где сохраняется состояние сессии (прогресс закачек), чтобы после перезагрузки сервера не начинать всё с нуля.
*   **`oauth`**: Объект для работы с Google OAuth2.

---

### 2. Вспомогательные функции (Dependencies)
Эти функции используются как инструменты для защиты и работы с данными.
*   **`get_db()`**: Генератор сессии базы данных (SQLAlchemy). Гарантирует, что соединение закроется после запроса.
*   **`create_access_token(data)`**: Создает JWT-токен (JSON Web Token) для авторизации пользователя.
*   **`get_current_user(...)`**: 
    *   Достает токен из куки.
    *   Проверяет его валидность.
    *   Ищет пользователя в БД. Если его нет — **автоматически регистрирует** (создает профиль).
    *   Если email в списке `ADMIN_EMAILS`, дает права администратора.
*   **`admin_required(...)`**: Проверка: если пользователь не админ, выдает ошибку `403 Forbidden`.

---

### 3. Торрент-логика (Core Engine)
Это "сердце" системы, работающее в фоновом режиме.

*   **`resume_downloads_on_startup(db_factory)`**: 
    *   Запускается один раз при старте сервера.
    *   Сканирует БД на наличие незавершенных торрентов (`counted == False`).
    *   Заново добавляет их в `libtorrent` и запускает мониторинг.
*   **`torrent_monitor(handle, db_factory, user_email)`**: 
    *   **Самая важная функция.** Работает в бесконечном цикле `while True` для каждого торрента.
    *   Каждые 3 секунды берет статус из `libtorrent` (скорость, прогресс, пиры).
    *   Записывает эти данные в JSON-поле `metadata_json` в базе данных.
    *   **Логика статистики:** Если торрент докачан (`progress >= 0.999`), она прибавляет объем файла к `total_downloaded_mb` пользователя и увеличивает счетчик файлов.
    *   Ставит метку `counted: True`, чтобы статистика не начислялась повторно.

---

### 4. API Эндпоинты (Endpoints)

#### **Авторизация**
*   **`GET /auth/login`**: Редирект пользователя на страницу входа Google.
*   **`GET /auth/callback`**: Точка возврата от Google. Получает данные пользователя, создает/обновляет его в БД и устанавливает `access_token` в куки.
*   **`GET /status-check`**: Проверяет, залогинен ли пользователь, и возвращает его данные (аватар, лимиты, статистика).
*   **`GET /auth/logout`**: Удаляет куку с токеном.

#### **Управление торрентами**
*   **`POST /torrent/file`**: 
    *   Принимает `.torrent` файл.
    *   Проверяет лимит на количество торрентов по подписке.
    *   **Логика Shared Library:** Если файл с таким хешем уже есть в системе (его качает другой юзер), он просто создает запись в БД для текущего юзера, но **не запускает** новую закачку.
*   **`POST /torrent/magnet`**: Принимает Magnet-ссылку. Аналогично файлу, но с ожиданием метаданных (т.к. magnet-ссылке нужно время, чтобы "понять", что именно качать).
*   **`GET /torrent/download/{hash}`**: 
    *   Проверяет, не превысил ли пользователь свой лимит по объему (МБ).
    *   Ищет файл на диске и отдает его пользователю через `FileResponse`.
*   **`GET /torrent/all`**: Возвращает список всех торрентов, которые принадлежат текущему пользователю, с их текущим статусом из БД.

#### **Администрирование**
*   **`POST /admin/set/levels`**: Создание нового тарифного плана (название, лимит МБ, лимит торрентов).
*   **`PATCH /admin/users/{id}/subscription`**: Назначение подписки конкретному пользователю.
*   **`GET /admin/users`**: Список всех пользователей и их статистики для контроля.
*   **`GET /subscribe/levels`**: Список всех доступных тарифов.

---

### Резюме по архитектуре:
1.  **Безопасность:** Все действия защищены JWT-токенами и проверкой прав (Admin/User).
2.  **Масштабируемость:** Использование `asyncio` позволяет серверу обрабатывать сотни торрентов одновременно, не блокируя основные запросы.
3.  **Экономия ресурсов:** Благодаря проверке `info_hash`, система не качает один и тот же файл дважды, если его запросили разные люди.
4.  **Надежность:** Состояние сессии `libtorrent` и данные в БД синхронизированы, что позволяет серверу "проснуться" и продолжить работу после сбоя.
